# MarinaFrame 0.4 — decision summary

**7 November 2026, Asia/Singapore.** MarinaFrame now has a functioning Rust domain harness around the existing Python/CadQuery/OpenCascade engine. It continues the exact published 0.3 source in draft PR #2. All new commits remain local; nothing was pushed, merged or deployed.

## What now works

The cached failed-validation defect was reproduced in unmodified 0.3, repaired and independently reviewed. Fresh validation, cached validation, restart and finalization now retain a failed audit. The old defect reached review-ready status while engineering approval remained false. An actual retained native failure at 43.264475 mm against a 1.1 mm gate stays failed.

Rust owns task state, typed decisions, durable events, request accounting, process supervision, cancellation and finalization. Its Python bridge invokes the domain tools directly; the old Python harness does not control the new workflow. The model can choose captured source alternatives and request six constrained operations. It cannot write arbitrary CAD code, invent coordinates, change units or tolerances, or grant engineering approval. Blender is not used.

The real browser workflow supports alternative selection, regeneration, stale-tab rejection, cancellation/resume and an inspectable history. The tested native UI trajectory had three builds and five explicitly recorded assistant interventions. It remained a provisional candidate requiring human review.

## What DeepSeek demonstrated

Actual live DeepSeek requests received images reimported from exported STEP, changed the selected source interpretation, rebuilt and revalidated. This full visual correction succeeded in **2 of 6 repeated controlled development trials**; four abstained. The initial incorrect grid-line selection was deliberately seeded, so this is a controlled capability result, not an autonomous reconstruction success rate.

Independent measurements of one successful correction found sampled half-breadth RMS decrease from **2.880574 m to 0.048361 m**. A **1.302507 m local endpoint error remained**. Four earlier natural continuations retained the historical centroid interpretation. The useful revision is real, and reliable semantic interpretation remains unresolved.

Across the new campaign there were **224 intended requests: 223 completed and one failed schema response**, with 2,196,623 reported prompt tokens and 15,871 completion tokens. All 224 receipts explicitly reported observed cost 0. That is provider-reported usage, not a claim about the account invoice. The historical 0.3 uncertain reservation remains uncertain and separate. The campaign had no aggregate request/token/spend cap; bounded requests, workers and no-progress handling remained in force.

## Accuracy and Rust migration

In the sealed final evaluation, published 0.3, current Python, current Rust and live DeepSeek each passed **8/8 supported drawings from four paired families**. Published 0.2 passed 4/8. Current Python/Rust/live produced identical geometry. **There was no supported-geometry pass-rate gain over 0.3 or from live assistance on this set.** Rust/live gave explicit blocks or abstentions on the diagnostics; the report preserves a questionable original interior-loop refusal label and a separate sensitivity analysis. All arms withheld ready hulls on three incomplete authentic sheets, which have no 3D gold. The full ledger retains 92 primary executions plus the 30-attempt initial intake preflight cohort (24 procedural attempts affected by fractional ROI bounds and six unchanged authentic-partial attempts). A separately selected assistant sample passed one supported case and abstained on one ambiguous case; no human engineer participated.

In a separate controlled parity comparison, all six successful Python/Rust pairs produced byte-identical STEP DATA sections. Rust took **4.0–11.3% longer** across three case types; two repetitions per type are too few for a general performance claim. Rust improved ownership and enforceable contracts, not hull geometry or native CAD speed. Native processes still dominated memory use.

## Data, actual learning and remaining gaps

Six additional ALMA source files were acquired, taking the local inventory to **11 authentic items from four vessels**. They add one vessel, not six independent designs. Local training/testing was owner-authorized; uninspected provider-transfer and redistribution scope is recorded separately. The unrestricted package includes the exact cleared five-item subset and omits restricted ALMA bytes.

A small **18,594-parameter classifier was actually trained**, with checkpoints, predictions and failed examples retained. On its narrow procedural test it reached **96.5856% balanced accuracy versus 80.7870%** for the heuristic. Supplied isolated ink locations, excluded crossings and synthetic labels limit that result. It is not enabled in reconstruction; DeepSeek was not fine-tuned. There are still **zero expert-reviewed authentic gold sets and zero authentic whole-hull ground truths**.

The optional learning setup was corrected from Pillow 12.3.0 to 13.0.0 after a dependency audit. The patched environment reproduced all 1,728 saved test predictions exactly. Known VTK advisories and off-target license-review gaps remain documented.

The next highest-value work is independently reviewed real line, endpoint and calibration evidence, followed by semantic selection and broader geometric representation. A named accessible modern licensed collection/account and qualified engineering review are still missing. Every delivered candidate remains **`engineering_approved=false`**. This release proves a constrained research harness and a controlled live revision capability; it does not establish shipyard-grade reconstruction, structural design, stability or fabrication readiness.

The full report, per-case results, failures, exact verification commands, source history and manifests accompany this summary.
